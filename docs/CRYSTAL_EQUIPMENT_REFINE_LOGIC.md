# 水晶装备洗炼词条数量计算逻辑

## 概述

洗炼系统根据装备配置、锁定的稀有词条和随机概率来生成新词条。

**核心规则**：
- **只有稀有词条可以锁定**，普通词条每次洗炼都会重新生成
- 普通词条固定生成 `entryNum` 个
- 稀有词条：先保留锁定的，剩余配额根据概率生成

## 配置参数

从 `TplCrystalEquipmentRefinement` 表中获取：
- `entryNum`: 普通词条固定数量
- `rareEntryNum`: 稀有词条最大配额
- `rareEntryWeight`: 稀有词条触发权重（0-10000）
- `maxRatio`: 词条数值上限百分比

## 计算流程

### 1. 统计锁定的稀有词条

```
只有稀有词条（Quality == 1）可以被锁定
锁定的稀有词条数 = 遍历 LockedAffixIds，统计 Quality == 1 的词条
```

**示例**：
- 尝试锁定3个词条：AF10001(普通), AF10013(稀有), AF10005(普通)
- 实际只有 AF10013(稀有) 被成功锁定
- 锁定的稀有词条数 = 1

### 2. 生成普通词条

```
生成的普通词条数 = entryNum（固定值，不受锁定影响）
```

**特点**：
- 普通词条**每次洗炼都完全重新生成**
- 不能锁定普通词条
- 数量固定为配置的 `entryNum`

**示例**：
- 配置 `entryNum = 4`
- 无论是否有锁定，都生成 **4个全新的普通词条**

### 3. 生成稀有词条

稀有词条生成分为三步：

#### 步骤 A：添加锁定的稀有词条

```
直接保留所有锁定的稀有词条（包含ID和数值）
```

#### 步骤 B：计算剩余稀有词条配额

```
剩余配额 = rareEntryNum - 锁定的稀有词条数
```

**示例**：
- `rareEntryNum = 2`（最多2个稀有词条）
- 锁定的稀有词条数 = 1
- 剩余配额 = 2 - 1 = 1

#### 步骤 C：每个稀有词条槽位独立判断概率

**重要**：每个剩余的稀有词条槽位独立进行概率判断，不是一次性判断所有槽位。

```
新生成的稀有数 = 0

对于每个剩余槽位（从1到剩余配额）：
    随机值 = rand(0, 10000)
    
    如果 随机值 < rareEntryWeight：
        新生成的稀有数 += 1  // 该槽位触发成功
    否则：
        // 该槽位未触发，继续判断下一个槽位
```

**示例 1（剩余1个槽位）**：
- 剩余配额 = 1
- `rareEntryWeight = 5000`（50%概率）
- 槽位1：随机值 = 3000 < 5000，触发 ✓
- 新生成的稀有数 = 1

**示例 2（剩余2个槽位，都触发）**：
- 剩余配额 = 2
- `rareEntryWeight = 2000`（20%概率）
- 槽位1：随机值 = 1500 < 2000，触发 ✓
- 槽位2：随机值 = 1800 < 2000，触发 ✓
- 新生成的稀有数 = 2

**示例 3（剩余2个槽位，部分触发）**：
- 剩余配额 = 2
- `rareEntryWeight = 2000`（20%概率）
- 槽位1：随机值 = 1500 < 2000，触发 ✓
- 槽位2：随机值 = 7000 > 2000，未触发 ✗
- 新生成的稀有数 = 1

**示例 4（剩余2个槽位，都未触发）**：
- 剩余配额 = 2
- `rareEntryWeight = 2000`（20%概率）
- 槽位1：随机值 = 8000 > 2000，未触发 ✗
- 槽位2：随机值 = 6500 > 2000，未触发 ✗
- 新生成的稀有数 = 0

## 完整示例

### 场景设置
- 装备品质配置：`entryNum = 4`, `rareEntryNum = 2`, `rareEntryWeight = 5000`
- 当前激活词条：
  - AF10001(普通, value=50)
  - AF10002(普通, value=60)
  - AF10013(稀有, value=5)
  - AF10003(普通, value=55)
- 尝试锁定：AF10001(普通), AF10013(稀有)
- 实际锁定：AF10013(稀有) ✓，AF10001(普通) ✗（普通词条不能锁定）

### 计算过程

**1. 统计锁定的稀有词条**
```
锁定的稀有词条数 = 1（只有 AF10013）
注意：AF10001 是普通词条，不能被锁定
```

**2. 生成普通词条**
```
生成的普通词条数 = 4（固定值，每次都全部重新生成）
```

**3. 生成稀有词条**

步骤 A：添加锁定的稀有词条
```
保留：AF10013(稀有, value=5)
```

步骤 B：计算剩余配额
```
剩余配额 = 2 - 1 = 1
```

步骤 C：独立判断每个稀有词条槽位
```
配置：rareEntryWeight = 5000（50%概率）
剩余槽位数 = 1

槽位1判断：
  随机值 = 3000 < 5000，触发成功 ✓
  
新生成的稀有数 = 1
```

**4. 最终备用词条**
```
PendingAffixes = [
    AF10004(普通, value=45),       // 新生成
    AF10007(普通, value=70),       // 新生成
    AF10008(普通, value=38),       // 新生成
    AF10009(普通, value=52),       // 新生成
    AF10013(稀有, value=5),        // 锁定保留
    AF10014(稀有, value=4)         // 新生成
]
```

**关键点**：
- 普通词条 AF10001, AF10002, AF10003 被新的 AF10004, AF10007, AF10008, AF10009 替换
- 稀有词条 AF10013 因为被锁定而保留
- 新生成了1个稀有词条 AF10014

## 特殊情况处理

### 情况1：所有稀有词条槽位都未触发
```
锁定的稀有数 = 1
剩余配额 = 2 - 1 = 1
配置：rareEntryWeight = 5000（50%概率）

槽位1判断：
  随机值 = 7000 > 5000，未触发 ✗

新生成的稀有数 = 0

结果：
- 4个普通词条（全新生成）
- 1个稀有词条（锁定保留）
```

### 情况2：稀有配额已满
```
锁定的稀有数 = 2
剩余配额 = 2 - 2 = 0
新生成的稀有数 = 0（无配额）

结果：
- 4个普通词条（全新生成）
- 2个稀有词条（全部来自锁定）
```

### 情况3：没有锁定任何词条，独立判断2个槽位
```
锁定的稀有数 = 0
剩余配额 = 2 - 0 = 2
配置：rareEntryWeight = 2000（20%概率）

槽位1判断：
  随机值 = 1500 < 2000，触发 ✓
  
槽位2判断：
  随机值 = 7500 > 2000，未触发 ✗

新生成的稀有数 = 1

结果：
- 4个普通词条（全新生成）
- 1个稀有词条（随机生成）
```

**概率分析**（20%概率，2个槽位）：
- 0个稀有：(0.8 × 0.8) = 64%
- 1个稀有：2 × (0.2 × 0.8) = 32%
- 2个稀有：(0.2 × 0.2) = 4%

### 情况4：尝试锁定普通词条
```
用户尝试锁定 AF10001（普通词条）
系统返回错误：Code=7, Msg="只能锁定稀有词条"
锁定失败，AF10001 不会被锁定
```

## 核心公式总结

```
生成的普通词条数 = entryNum（固定值）

锁定的稀有词条数 = 统计 LockedAffixIds 中 Quality == 1 的数量

剩余稀有配额 = rareEntryNum - 锁定的稀有词条数

新生成的稀有数 = 0
对于每个剩余槽位（i = 1 到 剩余稀有配额）:
    如果 rand(0, 10000) < rareEntryWeight:
        新生成的稀有数 += 1

最终稀有词条数 = 锁定的稀有数 + 新生成的稀有数
```

**概率计算示例**：
- 单个槽位概率 = rareEntryWeight / 10000
- 2个槽位，每个20%概率：
  - 0个稀有：80% × 80% = 64%
  - 1个稀有：2 × (20% × 80%) = 32%
  - 2个稀有：20% × 20% = 4%
