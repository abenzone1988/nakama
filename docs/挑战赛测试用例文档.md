# 挑战赛测试用例文档

## 概述

本文档详细说明了挑战赛系统的完整测试用例，涵盖了所有时间段、奖励机制、边界条件和异常情况的测试场景。

## 挑战赛业务逻辑概述

### 时间段说明
挑战赛有4个关键时间段：
- **OpenTime**: 比赛开始时间（玩家可以参加比赛）
- **CloseTime**: 比赛关闭时间（客户端判断不能进入游戏，但仍可提交成绩）
- **EndTime**: 比赛结束时间（不能再提交成绩）
- **OverTime**: 比赛结算时间（过后奖励变成邮件发送）

### 奖励机制
1. **积分奖励**: 根据成绩达到不同条件获得（低分、中分、高分）
2. **排位奖励**: 根据最终排名获得
3. **邮件奖励**: 结算时间后未领取的奖励通过邮件发送

### 主要接口
- `GetChallenge`: 获取挑战赛列表
- `JoinChallenge`: 参加挑战赛
- `GainChallengeReward`: 获得挑战赛奖励

## 测试用例结构

### 1. 综合时间段测试 (TestChallengeComprehensive)

测试挑战赛在不同时间段的行为表现：

#### 1.1 比赛开始前
- **预期行为**: 无法参加，但可以在GetChallenge中看到（作为下一场比赛）
- **测试要点**:
  - GetChallenge应该返回未来的比赛
  - JoinChallenge应该返回错误码4（"挑战赛未开放或已结束"）

#### 1.2 比赛开始时
- **预期行为**: 可以参加，可以提交成绩
- **测试要点**:
  - JoinChallenge应该成功
  - 可以提交成绩
  - GetChallenge应该显示已参加的比赛

#### 1.3 比赛进行中
- **预期行为**: 可以参加，可以提交成绩
- **测试要点**:
  - 正常参赛流程
  - 成绩提交功能
  - 竞标赛分配逻辑

#### 1.4 比赛关闭时
- **预期行为**: 客户端判断不能进入游戏，但还可以提交成绩
- **测试要点**:
  - JoinChallenge仍然可以成功
  - 成绩提交仍然有效
  - 客户端通过CloseTime判断不能进入游戏

#### 1.5 比赛结束时
- **预期行为**: 无法参加，无法提交成绩，可以手动领取奖励
- **测试要点**:
  - JoinChallenge应该失败
  - 无法提交新成绩
  - GainChallengeReward应该可以领取奖励

#### 1.6 比赛结算前
- **预期行为**: 无法参加，无法提交成绩，可以手动领取奖励
- **测试要点**:
  - 奖励领取功能正常
  - 积分奖励和排位奖励都可以领取

#### 1.7 比赛结算后
- **预期行为**: 无法参加，无法提交成绩，奖励变成邮件发送
- **测试要点**:
  - 自动邮件发送功能
  - GetChallenge应该返回GetReward=true
  - 邮件内容正确性

### 2. 奖励场景测试 (TestChallengeRewardScenarios)

测试不同成绩和排名情况下的奖励机制：

#### 2.1 无成绩玩家
- **场景**: 玩家参加但没有提交成绩
- **预期**: 不应该获得任何奖励
- **测试要点**: GainChallengeReward返回错误码5（"没有提交成绩"）

#### 2.2 低分玩家 (score >= Condition01)
- **场景**: 玩家达到低分条件
- **预期**: 获得低分奖励和排位奖励
- **测试要点**: 奖励数量和类型正确

#### 2.3 中分玩家 (score >= Condition02)
- **场景**: 玩家达到中分条件
- **预期**: 获得低分、中分奖励和排位奖励
- **测试要点**: 累积奖励逻辑正确

#### 2.4 高分玩家 (score >= Condition03)
- **场景**: 玩家达到高分条件
- **预期**: 获得所有积分奖励和排位奖励
- **测试要点**: 完整奖励发放

#### 2.5 边界分数玩家
- **场景**: 玩家分数刚好达到某个条件边界
- **预期**: 边界条件处理正确
- **测试要点**: 等于边界值时的奖励发放

#### 2.6 高分低排名玩家
- **场景**: 玩家分数高但排名相对较低
- **预期**: 获得所有积分奖励和对应排位奖励
- **测试要点**: 积分奖励和排位奖励独立计算

### 3. 边界条件测试 (TestChallengeBoundaryConditions)

测试各种边界情况和异常处理：

#### 3.1 重复参加挑战赛
- **测试要点**: 
  - 第一次参加成功
  - 第二次参加失败，返回错误码2（"挑战赛不可重复参加"）

#### 3.2 竞标赛满员情况
- **测试要点**:
  - 竞标赛达到MaxPart时创建新竞标赛
  - 新玩家能够成功加入新竞标赛
  - 批次编号正确递增

#### 3.3 重复领取奖励
- **测试要点**:
  - 第一次领取成功
  - 第二次领取失败，返回相应错误码

#### 3.4 时间临界点
- **测试要点**:
  - 各个时间点的精确处理
  - 时间边界的准确判断

#### 3.5 无效挑战赛ID
- **测试要点**:
  - 使用不存在的挑战赛ID
  - 返回错误码1（"挑战赛Id不存在"）

#### 3.6 邮件奖励发送
- **测试要点**:
  - 过期奖励自动变成邮件
  - 邮件内容和格式正确

### 4. 排名场景测试 (TestChallengeRankingScenarios)

测试不同排名情况下的奖励分配：

#### 4.1 基础排名测试
- **测试要点**:
  - 基本排名计算正确
  - 排名奖励分配准确

#### 4.2 相同分数排名测试
- **测试要点**:
  - 相同分数玩家排名处理
  - 并列排名的奖励分配

#### 4.3 大规模排名测试
- **测试要点**:
  - 大量玩家的排名计算性能
  - 排名奖励分配的正确性

### 5. 完整工作流程测试 (TestChallengeCompleteWorkflow)

测试完整的业务流程：

#### 5.1 正常参赛流程
- **流程**: GetChallenge → JoinChallenge → SubmitScore → GetChallenge → WaitForEnd → GainReward
- **测试要点**: 完整流程无异常

#### 5.2 迟到参赛流程
- **流程**: 比赛快结束时参加
- **测试要点**: 临近结束时参赛的处理

#### 5.3 错过手动领奖流程
- **流程**: 玩家错过手动领奖，奖励变成邮件
- **测试要点**: 邮件补发机制

#### 5.4 只参加不提交成绩流程
- **流程**: 参加但不提交成绩
- **测试要点**: 无成绩时的处理
