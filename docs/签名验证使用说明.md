# 排行榜和锦标赛记录签名验证使用说明

## 概述

为了防止客户端提交的排行榜和锦标赛记录数据被篡改，我们在 `WriteLeaderboardRecord` 和 `WriteTournamentRecord` 接口中添加了签名验证功能。

## 签名机制

### 签名算法
- 使用 HMAC-SHA256 算法生成签名
- 签名密钥可以在 `server/signature_utils.go` 中的 `DefaultSignatureConfig` 中配置
- 生产环境中应该从环境变量或配置文件中获取密钥

### 签名字段
签名通过 `metadata` 字段的 JSON 对象中的 `signature` 字段传递。

### 参与签名的数据
- **排行榜记录**: `leaderboard_id`, `score`, `subscore`, `metadata`（不包含signature字段）
- **锦标赛记录**: `tournament_id`, `score`, `subscore`, `metadata`（不包含signature字段）

## 使用方法

### 1. 生成签名（客户端）

#### 排行榜记录签名生成示例

```go
package main

import (
    "crypto/hmac"
    "crypto/sha256"
    "encoding/hex"
    "encoding/json"
    "fmt"
    "sort"
    "strconv"
    "strings"
)

func generateLeaderboardSignature(leaderboardID string, score, subscore int64, metadata string, secretKey string) (string, error) {
    data := map[string]interface{}{
        "leaderboard_id": leaderboardID,
        "score":          score,
        "subscore":       subscore,
        "metadata":       metadata,
    }
    
    // 将 map 转换为有序的字符串
    keys := make([]string, 0, len(data))
    for k := range data {
        keys = append(keys, k)
    }
    sort.Strings(keys)

    var parts []string
    for _, key := range keys {
        value := data[key]
        var valueStr string
        
        switch v := value.(type) {
        case string:
            valueStr = v
        case int64:
            valueStr = strconv.FormatInt(v, 10)
        default:
            valueStr = fmt.Sprintf("%v", v)
        }
        
        parts = append(parts, fmt.Sprintf("%s=%s", key, valueStr))
    }
    
    // 生成签名字符串
    signStr := strings.Join(parts, "&")
    
    // 使用 HMAC-SHA256 生成签名
    h := hmac.New(sha256.New, []byte(secretKey))
    h.Write([]byte(signStr))
    signature := hex.EncodeToString(h.Sum(nil))
    
    return signature, nil
}

func main() {
    // 示例数据
    leaderboardID := "daily-leaderboard"
    score := int64(1000)
    subscore := int64(500)
    secretKey := "nakama-default-secret-key"
    
    // 业务 metadata（不包含签名）
    businessMetadata := map[string]interface{}{
        "level":     1,
        "character": "player1",
    }
    
    // 将业务数据转换为JSON字符串
    businessMetadataJSON, _ := json.Marshal(businessMetadata)
    
    // 生成签名
    signature, err := generateLeaderboardSignature(leaderboardID, score, subscore, string(businessMetadataJSON), secretKey)
    if err != nil {
        fmt.Printf("生成签名失败: %v\n", err)
        return
    }
    
    // 添加签名到 metadata
    businessMetadata["signature"] = signature
    finalMetadata, _ := json.Marshal(businessMetadata)
    
    fmt.Printf("最终的 metadata: %s\n", string(finalMetadata))
}
```

### 3. 服务端验证

服务端会自动验证签名：

1. 从 `metadata` 中提取 `signature` 字段
2. 使用相同的算法生成预期签名
3. 比较提交的签名与预期签名
4. 如果验证失败，返回 `InvalidArgument` 错误
5. 如果验证成功，移除 `signature` 字段，只保留业务数据

## 错误处理

### 常见错误

1. **Signature is required. Please provide metadata with signature field.**
   - 缺少 metadata 或 metadata 为空
   - 现在强制要求所有记录都必须包含签名

2. **Signature field is required in metadata.**
   - metadata 中缺少 signature 字段
   - 必须在 metadata JSON 中包含 signature 字段

3. **Invalid signature. The data may have been tampered with.**
   - 签名验证失败，数据可能被篡改
   - 检查签名生成算法是否正确
   - 检查密钥是否一致
   - 服务端会记录详细的失败日志，包含玩家UUID、用户名和提交的数据

4. **Signature must be a string.**
   - signature 字段必须是字符串类型

5. **Invalid metadata JSON format.**
   - metadata 不是有效的 JSON 格式

6. **Error processing metadata for signature verification.**
   - 处理 metadata 时出现错误

### 日志记录

服务端会记录以下类型的日志：

#### 1. 缺少签名的日志
```
Record submission without signature rejected - signature is required
user_id: 玩家UUID
username: 玩家用户名
record_type: "leaderboard" 或 "tournament"
record_id: 排行榜ID或锦标赛ID
```

#### 2. 缺少签名字段的日志
```
Record submission without signature rejected - signature field missing
user_id: 玩家UUID
username: 玩家用户名
record_type: "leaderboard" 或 "tournament"
record_id: 排行榜ID或锦标赛ID
```

#### 3. 签名验证失败的日志
- **排行榜记录失败日志**：
  ```
  Leaderboard record signature verification failed
  user_id: 玩家UUID
  username: 玩家用户名
  leaderboard_id: 排行榜ID
  score: 提交的分数
  subscore: 提交的子分数
  metadata: 提交的业务数据
  signature: 提交的签名
  ```

- **锦标赛记录失败日志**：
  ```
  Tournament record signature verification failed
  user_id: 玩家UUID
  username: 玩家用户名
  tournament_id: 锦标赛ID
  score: 提交的分数
  subscore: 提交的子分数
  metadata: 提交的业务数据
  signature: 提交的签名
  ```

这些日志可以帮助管理员识别恶意玩家和分析攻击模式。

## 配置选项

### 修改签名密钥

在 `server/signature_utils.go` 中修改 `DefaultSignatureConfig`：

```go
var DefaultSignatureConfig = SignatureConfig{
    SecretKey: "your-production-secret-key", // 修改为您的密钥
    Algorithm: "HMAC-SHA256",
}
```

### 从环境变量获取密钥

```go
import "os"

func init() {
    if secretKey := os.Getenv("NAKAMA_SIGNATURE_SECRET_KEY"); secretKey != "" {
        DefaultSignatureConfig.SecretKey = secretKey
    }
}
```

## 签名验证规则

**重要提示：现在强制要求所有记录提交都必须包含签名！**

- 所有排行榜和锦标赛记录提交都必须包含 `metadata` 字段
- `metadata` 必须是有效的 JSON 格式
- `metadata` 中必须包含 `signature` 字段
- 如果缺少 `metadata` 或 `signature` 字段，提交将被拒绝
- 签名验证失败的请求将被拒绝并记录日志

## 向后兼容性

**注意：此版本不再向后兼容！**

- 旧版本的客户端如果没有签名将无法提交记录
- 所有客户端都需要更新以支持签名验证
- 建议在升级服务端之前确保所有客户端都已更新

## 注意事项

1. **密钥安全**: 确保签名密钥的安全性，不要在客户端代码中硬编码密钥
2. **时间戳**: 建议在签名数据中包含时间戳以防止重放攻击
3. **网络安全**: 使用 HTTPS 传输以防止中间人攻击
4. **密钥轮换**: 定期更换签名密钥以提高安全性

## 代码架构

### 统一的签名验证函数

为了减少代码重复，排行榜和锦标赛的签名验证逻辑已经统一到 `VerifyRecordSignature` 函数中。

- **函数位置**: `server/signature_utils.go`
- **函数名**: `VerifyRecordSignature`
- **参数**: `SignatureVerificationRequest` 结构体
- **返回值**: 验证后的 metadata（移除签名字段）和错误信息

### 主要特性

1. **强制签名验证**: 所有记录提交都必须包含签名
2. **统一错误处理**: 所有签名相关错误都有统一的处理逻辑
3. **详细日志记录**: 记录所有签名验证失败的详细信息
4. **代码复用**: 排行榜和锦标赛使用相同的验证逻辑
