# 果力防线 IP 直连部署

目标主机 `39.101.186.196`，SSH 用户 `root`。部署目录 `/opt/fruit-ip`，独立 Compose 项目 `fruit-ip`，运行现有镜像 `docker.sparkinfi.com/nakama/fruit:latest`。本套配置只创建 PostgreSQL 与 Nakama，不创建 Nginx 或 Certbot，也不修改主机原有代理服务。

- HTTP API：`http://39.101.186.196:7550`，健康检查路径 `/healthcheck`。
- 管理后台：`http://39.101.186.196:7551`。
- 客户端：`scheme=http`、`host=39.101.186.196`、`port=7550`，`serverKey` 与服务器 `.env` 中 `SOCKET_SERVER_KEY` 保持一致。
- WebSocket 使用 `ws://39.101.186.196:7550`，由 Nakama SDK 根据 HTTP 客户端配置创建连接。
- PostgreSQL 不映射宿主机端口，避免与现有 5432 端口冲突；容器内连接 `postgres:5432`。
- 数据库文件：`/data/fruit-ip/postgres`；更新前 SQL 备份：`/data/fruit-ip/backups`。

目标主机是 CentOS 7，已有 Docker 26.1.4、Compose 2.27.1、Harbor 和多个原生 Nakama 进程。检查时 7350/7351、7750/7751、7850/7851 已被占用，7550/7551 空闲。新服务只映射后两个端口；各容器内的 7350/7351 使用独立网络，无须修改。主机内存约 1.7GB，每个新增容器设置 384MB 内存上限。

此主机使用 3.10 内核。实测当前 `postgres:16-alpine`（Alpine 3.24.2、PostgreSQL 16.15）初始化失败，系统调用跟踪确认 `pwritev2` 返回 EPERM；隔离测试中默认 seccomp 失败、禁用 seccomp 后成功。实际部署采用 `postgres:16-bookworm` 的 Debian 版本解决兼容性问题，保留默认容器安全策略。对应私有镜像为 `docker.sparkinfi.com/nakama/fruit-postgres:16-bookworm`，不要直接改回 Alpine 的滚动标签。

此主机的 `/data` 当前位于系统盘，没有单独的数据盘；部署前系统盘约剩余 11GB。数据库目录以宿主机绑定方式持久化，容器重建不会清空数据。这里创建新的独立数据库，不复制 `119.29.221.150` 上的玩家数据；两台机器的后台密码和会话签名密钥独立。

首次初始化：将本目录上传至 `/opt/fruit-ip` 后，运行以下命令。`prepare.sh` 会生成独立随机密码，不会覆盖已有 `.env`。

```bash
cd /opt/fruit-ip
bash prepare.sh
docker login docker.sparkinfi.com
bash init.sh
```

Harbor 使用现有 Docker 登录凭据，密码不写入脚本。后台用户默认为 `admin`，root 可使用 `grep '^CONSOLE_PASSWORD=' /opt/fruit-ip/.env` 查看密码。IP 直连使用明文 HTTP，本配置未启用 TLS；云安全组需要允许客户端访问 TCP 7550，并允许管理来源访问 TCP 7551。

日常操作：

```bash
cd /opt/fruit-ip
docker compose ps
docker compose logs --tail=200 -f nakama
bash restart_nakama.sh
# 先在构建机推送新 latest，再在此执行更新
bash update_nakama.sh
```

更新脚本只拉取并重建本项目 Nakama，更新前备份本项目数据库。请保留 `.env` 和 `/data/fruit-ip`。不要通过重启 Docker 或停止其他 Nakama 进程来更新本服务。
