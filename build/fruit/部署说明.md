# 果力防线单节点部署

本目录参考 `D:/GameServer/docker-hjzx/fruit/` 的 Compose、初始化、重启和更新脚本重新整理。部署目标为公网 `119.29.221.150`、内网 `172.16.32.11`，SSH 用户 `root`，服务器目录 `/opt/fruit`。项目名称为 Nakama，Harbor 项目为 `nakama`，镜像仓库为 `docker.sparkinfi.com/nakama/fruit`。

此文档和脚本不保存服务器初始密码。首次 SSH 登录时使用单独提供的密码。现有 fruit 目录中的外部数据库、Redis、Loki 地址及账户密码不沿用。

## 1. 部署结构与前提

2026-10-23 新增 `afagame223.com` 域名入口：

- `https://fruit.afagame223.com` → Nakama HTTP/WebSocket 7350。
- `https://fruit-admin.afagame223.com` → Nakama 管理后台 7351。
- 两个域名的 A 记录指向 `119.29.221.150`。证书独立存放于 `/opt/fruit/certbot/conf/live/fruit.afagame223.com/`，由现有 `fruit-cert-renew.timer` 自动续期。
- 在已运行的本 Compose 项目中执行 `cd /opt/fruit && bash add-afagame223-domains.sh` 即可添加入口。脚本依赖现有 `fruit.conf` 中的 WebSocket map，保留原域名配置，不重建数据库或 Nakama 容器；失败时恢复新增入口的原配置。
- Nginx 配置为 `/opt/fruit/nginx/conf.d/afagame223.conf`。客户端使用 `https`、`fruit.afagame223.com`、端口 `443`；WebSocket 使用 `wss`。

- `https://fruit.sparkgalaxy.cn` → Nginx 443 → Nakama HTTP/WebSocket 7350；客户端使用此域名、443、TLS。
- `https://fruit-admin.sparkgalaxy.cn` → Nginx 443 → Nakama 管理后台 7351。
- PostgreSQL 16 位于 Compose 内网 `postgres:5432`，数据库及用户均为 `fruit`。容器 `/var/lib/postgresql/data` 直接映射到宿主机数据盘 `/data/fruit/postgres`，数据库备份位于 `/data/fruit/backups`。
- 宿主机仅在回环地址开放 7350、7351 用于诊断；数据库、gRPC、Prometheus 不映射公网端口。
- Nginx 与 Certbot 都通过 Docker 运行；systemd 定时器每天两次检查证书续期，成功后重新加载 Nginx。
- 服务崩溃及服务器重启后由 `unless-stopped` 恢复；Docker 标记 `unhealthy` 本身不会自动重启服务，脚本会在健康检查失败时返回错误。

服务器要求 Linux、systemd、Docker Engine、Compose v2、Bash、OpenSSL、curl 和 flock（通常来自 util-linux），架构为 x86_64。安全组和系统防火墙放通 TCP 80/443，22 限制为运维来源；80 需要持续开放用于 HTTP-01 证书验证。部署前检查现有 80/443 占用，不要直接停止未知服务。

`/data` 必须是已挂载且已配置开机自动挂载的数据盘。本机为 `/dev/vdb`、ext4、约 100GB，已配置 `/etc/fstab`。`init.sh` 调用 `prepare-storage.sh` 检查挂载并创建数据目录，同时写入 `/etc/systemd/system/docker.service.d/fruit-data.conf`，使 Docker 开机启动等待 `/data` 挂载。Compose 禁止自动创建缺失的数据库绑定目录，避免数据盘未挂载时误初始化到系统盘。

**两个域名的公网 A 记录都必须指向 `119.29.221.150`**；若有 AAAA 记录，也必须能通过 IPv6 访问相同服务，否则先删除无效 AAAA。本次部署已在目标服务器上确认两个域名均解析为该公网 IP。可在腾讯云 DNS 控制台或公共 DNS 查询确认；本机代理软件可能返回 `198.18.*` 的虚拟地址，不应据此修改真实 DNS。

也可设置一条主机记录 `*`、类型 `A`、值 `119.29.221.150`，通过泛解析覆盖尚未单独配置的子域名，再由 Nginx `server_name` 选择上游端口。仅配置 `@` 主域名不会自动覆盖子域名。显式子域名记录优先于泛解析；本次已有 `fruit` 和 `fruit-admin` 两条记录，可以继续使用，无须修改。DNS A 记录只指定 IP，不指定服务端口；端口分流由 Nginx 完成。添加新域名时还需要配置对应 Nginx 虚拟主机与 HTTPS 证书。

## 2. 在 Windows 构建并推送镜像

启动 Docker Desktop，切换 Linux containers。在 Harbor 确认已有 **nakama** 项目且当前账户具有推送权限，然后在 PowerShell 执行：

```powershell
cd D:\GameServer\nakama
git branch --show-current
git status --short
docker login docker.sparkinfi.com
.\build\build-fruit.bat --version fruit-20261021-01
```

脚本参考 `build/build-hjzx-us.bat`，默认 Linux amd64，推送版本标签与 `latest` 两个标签。未指定 `--version` 时使用当前 Git 短提交号。构建内容是**当前工作目录（包含未提交的更改）**，不会切换分支；本次检查分支为 `果力防线-单节点`。工作区有未提交修改时，每次发布应指定不同版本标签，方便追踪和回退。

```powershell
# 仅构建并加载本地，不推送
.\build\build-fruit.bat --version fruit-test --no-push
```

`build/Dockerfile.fruit` 基于原 Dockerfile，额外把 `data/*.json` 游戏配置带入运行镜像，避免新数据库启动时缺少模板。此分支为单节点，不配置 Redis。运行配置来自本目录 `config.yml`，数据库和认证参数由服务器 `.env` 注入。镜像内不包含旧环境的 Lua 模块；若今后启用 Lua，请明确添加需要的模块，不要直接挂载旧项目目录。

只有镜像推送成功后才执行服务器更新。

目标服务器直连 Docker Hub 超时，因此 `.env.example` 默认使用已同步至 Harbor `nakama` 项目的三个依赖镜像。需要刷新这些依赖时，在能访问 Docker Hub 的 Windows 构建机执行：

```powershell
.\build\push-fruit-deps.ps1
```

该脚本将官方 PostgreSQL、Nginx、Certbot 的 amd64 镜像原样拉取并重新标记推送，不在服务器重新构建依赖。

## 4. 初始化 Compose 与 HTTPS

服务器上执行：

```bash
cd /opt/fruit
# 兼容 Windows Git 可能产生的 CRLF；Bash 脚本必须为 LF。
sed -i 's/\r$//' ./*.sh .env.example config.yml docker-compose.yml nginx/*.template
chmod 700 ./*.sh
bash prepare.sh
vi .env
```

在 `.env` 可选填写 `LETSENCRYPT_EMAIL=你的运维邮箱`，不要加引号。留空时通过 Certbot 注册无邮箱账户，仍自动申请并续期证书。该邮箱用于账户联系方式，Let’s Encrypt 已于 2025 年停止证书到期邮件服务，自动续期由本机 systemd 定时器执行，不依赖邮件。默认拉取 `latest`；首次部署推荐改成刚刚推送的版本标签，例如：

```dotenv
NAKAMA_IMAGE=docker.sparkinfi.com/nakama/fruit:fruit-20261021-01
LETSENCRYPT_EMAIL=ops@example.com
```

`prepare.sh` 自动生成互不相同的数据库、后台、会话签名密码。它不会覆盖已有 `.env`。数据库密码保持生成的十六进制格式，避免 URL 中特殊字符需要额外编码。`SOCKET_SERVER_KEY=sparkgame` 沿用当前客户端配置，如修改须同步客户端。后台默认用户 `admin`，密码见 `.env` 中的 `CONSOLE_PASSWORD`，与服务器 root 密码独立。

```bash
docker login docker.sparkinfi.com
bash init.sh
```

初始化顺序：校验配置并拉取镜像 → 等待 PostgreSQL 就绪 → Nakama 执行 `migrate up` 并启动 → HTTP Nginx 提供证书验证目录 → Certbot 申请覆盖两个域名的证书 → 启用 HTTPS 代理 → 安装自动续期定时器 → 验证两个 HTTPS 入口。

首次证书失败时保留 HTTP 验证服务，修复 DNS、80 端口、安全组或邮箱后重新执行 `bash init.sh`。没有证书时 HTTP 普通请求返回 503 属于预期行为。Nakama 第一次启动不会导入旧环境玩家数据，本部署会创建新数据库；若需要旧数据，须单独安排迁移。

## 6. 重启与更新

```bash
cd /opt/fruit
# 只重启当前 Nakama 容器，等待就绪并重新加载 Nginx
bash restart_nakama.sh
```

更新操作必须先在 Windows 构建推送新镜像。服务器 `.env` 若使用固定版本标签，先改成新标签；若希望每次拉取最新版，设置 `NAKAMA_IMAGE=docker.sparkinfi.com/nakama/fruit:latest`。然后执行：

```bash
cd /opt/fruit
bash update_nakama.sh            # 不备份，直接更新
bash update_nakama.sh --backup   # 更新前先导出数据库
```

更新脚本先确认 `/data` 已挂载，再拉取 Nakama 镜像；传了 `--backup` 时在拉取成功后导出数据库，随后停止旧 Nakama 并重建容器；新进程先执行数据库迁移，健康后重新加载 Nginx，刷新上游容器 IP。单节点更新有短暂停机，数据库和 Nginx 不重建。**默认不备份数据库**；`--backup` 导出全部业务数据，但 `wallet_ledger` 只保留表结构、不导出数据（流水表体积增长最快）。拉取或备份失败时保留原服务；迁移或健康检查失败时退出并输出日志，不会谎报成功，也不会自动执行可能不兼容的数据库回退。

```bash
# 故障定位
docker compose logs --tail=200 nakama postgres nginx
# 查看本地保留的版本
docker image ls docker.sparkinfi.com/nakama/fruit
```

回退二进制前确认数据库 schema 兼容，然后把 `.env` 的镜像改回旧版本，再运行更新脚本。若迁移不向后兼容，只能停服后从更新前的 `--backup` 备份恢复到经过验证的数据库实例（备份中 `wallet_ledger` 无数据，流水会丢失）；恢复会丢失备份后的写入。不要删除 `/data/fruit/postgres`；当前为宿主机目录绑定，重建容器不会删除这些数据。旧 Docker 数据卷暂时保留用于迁移回退，不要执行 `docker volume prune` 等清理命令。

`.env` 和证书私钥只保存在服务器，定期另做异机备份。已初始化的 PostgreSQL 修改 `.env` 中密码不会修改数据库账户密码，须在数据库内同步变更。更新脚本默认不备份数据库，需要回退点时加 `--backup`（输出到 `/data/fruit/backups/`，不含 `wallet_ledger` 数据），并按保留策略自行清理。
